# Maintenance and validation

Use `.agents/skills/word-control` as the sole global installation and maintenance source for this setup. Keep backups outside skill discovery directories. Edit and validate this installation, then synchronize the repository copy and compare every file by SHA-256. Do not recreate additional global copies or discovery links under other skill directories. Keep machine-local maintenance history in the backup, outside the distributed manuals.

For documentation or UI-prompt changes only, validate the Skill frontmatter, `agents/openai.yaml`, relative links and command examples; exercise changed installation instructions in an isolated directory. Confirm runtime and test scripts are unchanged before synchronizing. The Word integration requirement below applies when runtime or test scripts change.

Ordinary commands use Windows Script Host (`cscript`), not Node.js. Tests require Windows desktop Word, PowerShell and Node.js.

Selection-readback acceptance checks exact text and consistent lengths from `selection`, `status` and `selection-info` in body text, a header, a table cell and an insertion point. Compare document content/formatting, save state, selection coordinates and source bytes before/after. Microsoft's [Selection.Text contract](https://learn.microsoft.com/en-us/office/vba/api/word.selection.text) returns the character following an insertion point; the bridge explicitly returns empty text there while preserving the nonempty-selection behavior. Pure checks require that no native selection text is read for an empty range.

Scratch-output acceptance uses real FSO [ShortPath](https://learn.microsoft.com/en-us/office/vba/language/reference/user-interface-help/shortpath-property) aliases to reject input/document/output collisions before command execution, checks input hashes, and verifies that overwriting a separate scratch output still works. Pure checks cover both alias directions, unavailable identity and new outputs without existing-file identity reads. Volumes without a distinct short alias report `skipped-no-short-alias`; do not change filesystem settings to manufacture coverage. This covers Windows 8.3 spelling, not arbitrary hard links, reparse points or concurrent path replacement.

The open-security scenario observes `AutomationSecurity` from Word's actual `DocumentOpen` event using the existing C# COM event-sink pattern. Starting from each valid security mode (1, 2, 3), require mode 3 during opening, restoration of the prior value afterward, and unchanged existing-document state and source bytes. Pure regressions cover failed/unconfirmed preparation, combined open/restoration failures and cleanup limited to an empty command-owned Word instance. This verifies the programmatic-open boundary with synthetic documents; it does not execute macros or change registry/Trust Center policy. Microsoft documents the [default low automation setting and restoration requirement](https://learn.microsoft.com/en-us/office/vba/api/word.application.automationsecurity), and defines [force-disable as mode 3](https://learn.microsoft.com/en-us/office/vba/api/office.msoautomationsecurity).

The save/output regression uses a C# COM event sink compiled by Windows PowerShell to cancel Word's `DocumentBeforeSave` event without macros or Trust Center changes. It checks both save commands, source bytes and independent document state, real exclusive locks on old backup/PDF outputs, successful replacement and save/close/reopen. A `DocumentBeforeClose` handler also introduces a late edit and requires its preservation after reopening. Pure regressions cover a cancelled save returning normally, unavailable/pending save state, generation/publication/restoration failures, recovery-path reporting and destination guards. Together these are three added regression scenarios; injected failures do not establish every native Word failure mode.

powershell -NoProfile -ExecutionPolicy Bypass -File "$env:USERPROFILE\.agents\skills\word-control\scripts\test_word_control.ps1"

The test creates a unique temporary DOCX in a hidden Word instance, runs pure regressions and command integration, and strictly parses every generated JSON output. It checks paragraph/cell pagination, literal search in main text and notes with Find-setting restoration, targeted equations, summary/text modes without mutation guards, partial-read errors, verified cell/table/border results, failure reporting after partial writes or rollback, guarded text/table/equation edits, backups, PDF export and cleanup. XML diagnostics are tested with real MSXML normalization and Word text, shading, border, row, column, merge and tracked-revision changes; experimental hashes are rejected for writes. It removes its own temporary artifacts.

Smoke-output acceptance injects a generation failure into a temporary bridge copy, exercises a real exclusive lock on the old output, and verifies successful replacement by reopening it in Word. Compare the prior-output and fixture hashes and confirm owned Word processes and staging directories are gone. Pure regressions additionally cover startup failure, unconfirmed/empty saves and publication failure. `smoke --overwrite` uses the existing recoverable publication path rather than deleting its destination before generation; [SaveAs2](https://learn.microsoft.com/en-us/office/vba/api/word.saveas2) itself can overwrite an existing file without prompting.

An existing Word session causes command integration to be skipped. `skipped-existing-word-session` is not complete validation and does not authorize synchronization. Never attach tests to or close the user's Word session. Run real command integration when Word is not already running, and confirm task-owned Word processes exit.

`-FixturePath` optionally exercises a copy of a specifically chosen document and checks that the original file hash stays unchanged. Synthetic integration alone does not establish complex-document layout fidelity; inspect a relevant rendered output when a change affects layout.

Validate the Skill frontmatter and its relative links after changing the manuals. Keep the editing workflow, command help and examples consistent with actual runtime behavior. Preserve the medical-manuscript formatting gate and fresh-target guards when reducing instructions.

For performance comparisons, measure complete equivalent workflows, including process startup and required verification, on disposable copies. Verified border results already provide the next expected fingerprint; measure removal of an unnecessary follow-up query separately from changes to the write implementation.

`tables --table N --compare-xml` is an opt-in experiment, not a faster mutation guard. Its `elapsed_ms` covers two XML captures, parsing, normalization, comparison and hashing; the command still performs the ordinary full inspection first. Do not compare that diagnostic substep against an entire write workflow or claim end-to-end write acceleration. Editing-session IDs are excluded because repeated Word exports can vary them without a content edit. All other package content remains, which may still yield unrelated changes or miss differences in effective COM properties. Passing the current fixtures does not establish general equivalence. Keep XML candidates out of write authorization until a separately reviewed change establishes suitable coverage and fallback behavior.

The parser explicitly preserves whitespace, including whitespace-only text. MSXML's default can strip those nodes; see Microsoft's [preserveWhiteSpace documentation](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/ms761353(v=vs.85)).

Before accepting a runtime change, define its affected scope and allowed differences, then compare before/after state independently of the production fingerprint. Read-only XML checks compare all story text, object counts, bookmark ranges, target-cell text/font/shading/borders, selection and save state. Cell-border checks preserve non-border state and all boundaries outside the target and its shared neighbors. Document tests also retain original-file hashes and save/reopen checks. These checks establish the tested scope, not arbitrary document fidelity; add relevant visual comparison when layout behavior changes.

Cell-text acceptance checks exact paragraph/manual-break characters, stale guards after a trailing paragraph change, pre-write refusal of nested cell markers, unaffected neighboring content, and a save/reopen plus swap-back comparison of stories, objects, bookmarks and formatting. Establish a saved/reopened fixture before that comparison: native Word can remove unused empty header/footer stories on first reopen even without a bridge mutation. Display cleanup is not a lossless text representation; Microsoft's [Range.Text contract](https://learn.microsoft.com/en-us/office/vba/api/word.range.text) also makes clear that it contains plain text, not rich formatting.

Cell-result acceptance injects an incomplete final inspection into a temporary bridge copy while retaining real Word writes. Require a nonzero exit and an unverified result that still records the applied write; never return an empty-string fingerprint as a successful inspection. Check successful result reuse, recovery, unaffected story text/objects/bookmarks/cell formatting and save/reopen. Shading comparisons exclude only the target background/texture changes and retain foreground color and neighboring formatting. Microsoft documents [background color](https://learn.microsoft.com/en-us/office/vba/api/word.shading.backgroundpatterncolor) and [texture](https://learn.microsoft.com/en-us/office/vba/api/word.shading.texture) as separate properties. Pure regressions cover thrown/incomplete final checks, interrupted writes, silent/throwing restoration failures and unreadable readback. These are result-handling fault injections, not reproduced native Office read failures.

Known upstream risk signals include Office.js issues [#5014](https://github.com/OfficeDev/office-js/issues/5014) (cross-paragraph bookmark omission), [#6059](https://github.com/OfficeDev/office-js/issues/6059) (image-related OOXML retrieval failure) and [#6803](https://github.com/OfficeDev/office-js/issues/6803) (shape-body reads changing formatting on Mac). They are not confirmed failures of this Windows COM path. Microsoft's [Range.WordOpenXML contract](https://learn.microsoft.com/en-us/office/vba/api/word.range.wordopenxml) only covers markup needed for the requested range. Do not infer complete bookmark, document or effective-style coverage from a stable range snapshot, use it for XML writeback, or treat the 32-bit diagnostic hash as collision-proof.

Structural-result acceptance covers all four row/column commands with real writes and injected incomplete final inspections. Independently check actual cell positions/text, surviving cell fonts/shading/borders, surrounding text, stories/objects/bookmarks and save/reopen. Capture surrounding text after the native table has been created and reopened; do not assume a fixed number of paragraph markers. Deletion fixtures deliberately seed empty rows/columns, so test recovery does not reconstruct deleted user content. Pure regressions cover interrupted writes, dimension mismatch, unreadable/invalid counts and concurrent final-inspection errors, requiring one mutation and both existing full guard inspections. The placement checks follow Microsoft's [Rows.Add](https://learn.microsoft.com/en-us/office/vba/api/word.rows.add) and [Columns.Add](https://learn.microsoft.com/en-us/office/vba/api/word.columns.add) contracts. These checks verify the tested scope, not arbitrary layout fidelity or transactional rollback.

Deletion acceptance covers ordinary table/equation removal, refusal of an unapproved tracked table deletion, explicitly permitted tracked deletion and an injected unavailable count read after real removal. Check the middle object among three targets, surviving objects and their formatting, surrounding text, other stories, bookmarks, revision policy/history and save/reopen. Word 16.0 retained tracked table/OMath objects in these fixtures even though the delete call returned; treat this as observed revision behavior, not an established Office defect. The [Range.Delete contract](https://learn.microsoft.com/en-us/office/vba/api/word.range.delete) defines zero as an unsuccessful deletion, and [TrackRevisions](https://learn.microsoft.com/en-us/office/vba/api/word.document.trackrevisions) controls whether edits are tracked. Pure regressions also cover no removal, interrupted writes, invalid counts and combined write/readback failures. Do not accept revisions or replay deletion to make a test pass.

An untracked display-equation fixture also retained an empty OMath after `Range.Delete` and save/reopen; `OMath.Remove` did not eliminate that empty paragraph-level object in the same fixture. Setting the target's [OMath.Type](https://learn.microsoft.com/en-us/office/vba/api/word.omath.type) to inline before deleting its range removed it while preserving the surrounding text. The command only performs this preparation with tracking off and reports its state independently of the delete call. Pure checks cover interrupted or silently ineffective preparation and a later failed deletion; native checks compare surviving formulas' types and paragraph formatting, and export the display-equation case before and after for visual review. This evidence does not establish identical behavior for every equation layout.

Microsoft documents [save cancellation](https://learn.microsoft.com/en-us/office/vba/api/word.application.documentbeforesave), the mutable [Saved flag](https://learn.microsoft.com/en-us/office/vba/api/word.document.saved) and the [background-save queue](https://learn.microsoft.com/en-us/office/vba/api/word.application.backgroundsavingstatus). A returned Save call alone is insufficient evidence. [FSO MoveFile](https://learn.microsoft.com/en-us/office/vba/language/reference/user-interface-help/movefile-method) does not roll back prior moves, so output publication explicitly retains the previous file and attempts restoration on failure. Even Win32 [ReplaceFile](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-replacefilew) has documented partial-failure states; the related [.NET issue #22157](https://github.com/dotnet/runtime/issues/22157) is a warning against assuming rename-like atomicity, not a reproduced Word bug. Do not claim crash durability or universal filesystem identity/alias coverage from these guards.
